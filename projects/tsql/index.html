Introduction — What and why

The database stores employees and free-form attributes such as Height = Tall or Weight = Heavy. A link table connects them, so each employee can have any number of attributes. EMP_Supervisor points back to another employee, which forms the org chart.

The two tasks

  • Task 1: every employee must have Weight = Thin
  • Task 2: every supervisor must have Height = Short

Each task has to update the attribute when it exists and insert it when it doesn't. The tables below show the data before and after each script.

Task 1 — Weight = Thin for everyone

1a — Cursor, one employee at a time 1st_task_SQL_Query.sql

A cursor walks the Employee table. For each row it checks whether a Weight attribute exists, then updates or inserts. Everything runs in one transaction:

BEGIN TRANSACTION;
DECLARE emp_cursor CURSOR FOR SELECT EMP_ID FROM Employee;
OPEN emp_cursor;
FETCH NEXT FROM emp_cursor INTO @EmpID;

WHILE @@FETCH_STATUS = 0
BEGIN
    IF EXISTS (SELECT 1 FROM EmployeeAttribute ea
               JOIN Attribute a ON ea.EMPATTR_AttributeID = a.ATTR_ID
               WHERE ea.EMPATTR_EmployeeID = @EmpID AND a.ATTR_Name = 'Weight')
        -- has a Weight: change its value
        UPDATE a SET a.ATTR_Value = 'Thin'
        FROM Attribute a JOIN EmployeeAttribute ea ON a.ATTR_ID = ea.EMPATTR_AttributeID
        WHERE ea.EMPATTR_EmployeeID = @EmpID AND a.ATTR_Name = 'Weight';
    ELSE
    BEGIN
        -- no Weight: create one and link it
        SET @AttrID = NEWID();
        INSERT INTO Attribute VALUES (@AttrID, 'Weight', 'Thin');
        INSERT INTO EmployeeAttribute VALUES (@EmpID, @AttrID);
    END
    FETCH NEXT FROM emp_cursor INTO @EmpID;
END

CLOSE emp_cursor; DEALLOCATE emp_cursor;
COMMIT TRANSACTION;

Task 2 — Height = Short for supervisors

2a — Set-based, all supervisors at once 2_task_SQL_QUERY.sql

No loop this time. The script finds (or creates) the Height = Short attribute once, then re-points every supervisor's Height link to it with one UPDATE, and adds it with one INSERT for supervisors that have no Height at all: 

-- Find the existing 'Height = Short' attribute, or create it
SELECT @HeightAttrID = ATTR_ID FROM Attribute
WHERE ATTR_Name = 'Height' AND ATTR_Value = 'Short';
IF @HeightAttrID IS NULL ... INSERT INTO Attribute ...

BEGIN TRANSACTION;

-- Supervisors that already have a Height: link them to 'Short'
UPDATE EmployeeAttribute SET EMPATTR_AttributeID = @HeightAttrID
WHERE EMPATTR_EmployeeID IN (SELECT DISTINCT EMP_Supervisor FROM Employee
                             WHERE EMP_Supervisor IS NOT NULL)
  AND EMPATTR_AttributeID IN (SELECT ATTR_ID FROM Attribute WHERE ATTR_Name = 'Height');

-- Supervisors with no Height at all: add the link
INSERT INTO EmployeeAttribute (EMPATTR_EmployeeID, EMPATTR_AttributeID)
SELECT DISTINCT e.EMP_ID, @HeightAttrID FROM Employee e
WHERE e.EMP_ID IN (SELECT EMP_Supervisor FROM Employee WHERE EMP_Supervisor IS NOT NULL)
  AND NOT EXISTS (SELECT 1 FROM EmployeeAttribute ea
                  JOIN Attribute a ON ea.EMPATTR_AttributeID = a.ATTR_ID
                  WHERE ea.EMPATTR_EmployeeID = e.EMP_ID AND a.ATTR_Name = 'Height');

COMMIT TRANSACTION;
(2 rows affected)   -- UPDATE: Greg and Oleg
(0 rows affected)   -- INSERT: both supervisors already had a Height
THE supervisors were updated with the new value: Height -> Short.

Cursor vs set-based

The difference between the two approaches
Task 1 — cursorTask 2 — set-based
Works onOne employee per loopAll supervisors in one statement
DecisionIF EXISTS per rowWHERE ... IN and NOT EXISTS
Statements runGrows with the number of employeesFixed: one UPDATE + one INSERT
Easy to readYes, step by stepYes, once you read it as sets
Scales to big tablesPoorlyWell
ℹ
Task 1 changes the Attribute row itself. That is safe here because each attribute row belongs to one employee. If several employees shared one Weight = Medium row, updating it would change all of them. Task 2 avoids this by re-linking employees to a Height = Short row instead of editing values.
